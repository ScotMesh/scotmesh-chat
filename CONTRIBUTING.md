# Contributing to scotmesh-chat

This service carries ScotMesh's conversation, so the bar is "boring to run".
Everything here is enforced by CI; `make check` runs the same gates locally.

## Before you push

```
make fmt check
```

`check` runs vet, golangci-lint, race tests (shuffled), coverage gates, the
patched reticulum-go suite and govulncheck. The Makefile selects the Go
toolchain pinned in `go.mod`.

## Code

- **Go, no cgo.** One static binary. Dependencies need a reason in the PR.
- **Logging is `log/slog`** with stable, lower_snake keys. Debug logging is
  kept, not stripped; it is off by default.
- **No global mutable state, no `init()` side effects.** Wire things together
  in `cmd/` and pass them down.
- **Every goroutine has an owner and a context.** Every queue is bounded and
  counts what it drops. Every network send has a timeout.
- **Never send on the transport dispatcher goroutine.** Link and packet
  callbacks hand work to a queue and return.
- **One writer owns hub state.** Adapters post requests to the core and read
  its events; they never take a lock shared with another adapter.
- **Errors are wrapped with `%w`.** Protocol outcomes that callers branch on are
  sentinel errors, and user-facing error text is written for the person reading
  it.
- **Interfaces are defined where they are consumed**, so the transport, clock
  and store can be faked in tests.
- **Persistence is atomic.** SQLite transactions for state; temp file, fsync and
  rename for anything else.
- **Validate at the edge.** Identity hashes are 32 hex characters, sizes are
  checked in bytes before decoding, and config with unknown keys is an error.

## Tests

- Table tests for every command, room mode and name rule.
- Wire formats get golden vectors in `testdata/`, generated by the reference
  implementation (Python `cbor2`/RNS), never only by our own encoder.
- Every parser of untrusted input has a `Fuzz*` target (`make fuzz`).
- Packages that start goroutines check for leaks.
- Coverage floors live in `scripts/coverage-gates.txt` and only go up. Every
  new core package adds its gate in the same PR.
- End-to-end checks run against a private Reticulum network with stock Python
  clients (`tests/e2e/run_all.sh`). They aren't part of CI — they need a
  Python venv with `rns`, `lxmf` and `nomadnet` installed — so run them by
  hand before a release or a deploy with schema or protocol changes.

## Commits and releases

- [Conventional Commits](https://www.conventionalcommits.org/):
  `feat(hub): …`, `fix(rrcsrv): …`, `docs(adr): …`.
- User-visible changes go in `CHANGELOG.md` in the same PR.
- Decisions that are hard to undo get an ADR in `docs/adr/`.
- Releases are tagged `vX.Y.Z`. `make build` is reproducible (`-trimpath`, no
  build ID), and the checksum goes in the release notes.

## Third-party code

- Code derived from rrcd (MIT) carries a header naming the rrcd file it ports,
  and the rrcd copyright stays in `NOTICE`.
- `third_party/reticulum-go` changes are separate commits and are described in
  its `SCOTMESH-PATCHES.md`. They are written to be offered upstream.
- rrc-hub and reticulum-group-chat have no licence. Nothing from them may be
  copied here; reading their history for lessons is fine.
